# 第 05 章：栈、栈帧与 call/ret

> 阶段零（00~05）不配 Makefile。
> 本章源码：[stack.asm](stack.asm)

## 1. 本章目标

前面几章一直在用 `sub rsp, 40` 和 `call`，但没解释栈到底怎么动。本章回答：

- `push` / `pop` 对 `RSP` 做了什么？
- `call` 和 `ret` 如何配合？
- 标准栈帧 `push rbp / mov rbp, rsp / sub rsp, 32` 每一行在做什么？
- 递归时栈如何增长？
- 为什么入口处直接 `ret` 不是可靠的退出方式？

程序用递归阶乘 `5! = 120` 作为可验证结果。递归本身沿用高级语言概念：函数把大问题拆成同类小问题，直到遇到基线条件。本章真正新增的是“每次调用在内存里留下什么”，而不是递归算法。

前置：第 03 章已经见过 `call/ret` 的使用；如果还不熟悉栈的直觉，先读前言 5.1～5.3。Windows ABI 的完整参数规则在第 06 章才系统整理，本章只推导当前函数需要的栈布局。

## 2. 知识点讲解

### 2.1 栈的基本操作

x64 的栈**向下增长**：`push` 时 `RSP` 减小，`pop` 时 `RSP` 增大。栈顶就是"当前 `RSP` 指向的位置"。

| 操作 | 效果 |
|---|---|
| `push rax` | `RSP -= 8`，然后把 `RAX` 写到 `[RSP]` |
| `pop rax` | 从 `[RSP]` 读到 `RAX`，然后 `RSP += 8` |
| `call label` | `RSP -= 8`，把返回地址写到 `[RSP]`，跳转到 `label` |
| `ret` | 从 `[RSP]` 弹出返回地址到 `RIP`，然后 `RSP += 8` |

`call` 和 `ret` 本质上是一对"压返回地址 + 跳"和"弹返回地址 + 跳"的配合。

### 2.2 Windows x64 栈的两条硬规则

1. **没有红区（red zone）**：不能往 `[rsp-8]` 之类未分配区域写数据，函数调用会覆盖它。（System V ABI 有红区，Windows x64 没有。）
2. **影子空间（shadow space）**：调用任何 Windows x64 函数前，调用者要在栈上留出 32 字节，供被调用者保存 `RCX/RDX/R8/R9` 的参数。即使函数只有 1 个参数，这 32 字节也必须留。

### 2.3 ABI 对齐四件事（阶段零总结）

1. **入口 `RSP % 16 == 8`**：`call` 压入 8 字节返回地址后，被调用函数看到的就是这个状态。
2. **`call` 指令执行时 `RSP % 16 == 0`**：调用者必须先把自己的栈对齐到 16。
3. **序言二选一**：
   - 叶子函数或不需要帧指针：`sub rsp, 40`（8 字节对齐 + 32 字节影子空间）；
   - 需要帧指针：`push rbp`（`% 16 == 0`）+ `mov rbp, rsp` + `sub rsp, 32`（影子空间）。
4. **非易失寄存器**：`RBX / RBP / RDI / RSI / R12~R15` 由被调用者保存；`RAX / RCX / RDX / R8~R11` 是易失的。

完整 ABI 四件套（`RCX/RDX/R8/R9` 参数传递、32 字节影子空间、16 字节对齐、非易失寄存器）会在第 06 章配 Makefile 后系统展开。

### 2.4 标准栈帧的逐行含义

```asm
push rbp        ; 保存调用者的帧指针；RSP 减 8 → %16==0
mov  rbp, rsp   ; RBP 指向保存旧 RBP 的位置
sub  rsp, 32    ; 当前私有 fact 示例分配 32 字节，保持 %16==0
```

此后 `[rbp]` 是旧 RBP，`[rbp+8]` 是返回地址，`[rbp-1]` 往下是本函数已分配的空间。`leave` 等于 `mov rsp, rbp; pop rbp`，把栈恢复到调用前。

必须进一步区分**局部变量区**和**下一次调用的影子空间**。按 Windows ABI，被调函数可以使用调用者预留的 32 字节影子空间，所以通用函数不能把 `[rsp]`～`[rsp+31]` 同时当成调用后仍必须保值的局部变量。

本章 `fact` 是源码完全可见的私有递归函数，其当前实现不会写调用者的影子空间，因此 `[rbp-4]` 在这个特定示例中可以保存 `n`。若要写成不依赖被调函数内部实现的通用 ABI 栈帧，应额外分配局部变量区，例如：

```asm
push rbp
mov  rbp, rsp
sub  rsp, 48        ; 32 字节 outgoing 影子空间 + 16 字节局部/对齐空间
; [rbp-16]～[rbp-1]：局部变量
; [rsp]～[rsp+31]  ：仅供被调函数使用的影子空间，不与局部变量重叠
```

也就是说，本章源码展示的是最小递归实验，不应把“32 字节既当局部变量又当任意调用的影子空间”复制成通用模板。

### 2.5 递归时栈的增长

每次递归调用，栈上多出一帧：

```text
8   返回地址（call 压入）
8   保存的 RBP（push rbp）
32  当前私有示例分配的栈空间（sub rsp, 32；通用函数应另分局部区与影子空间）
── 合计 48 字节/层
```

`fact(5)` → `fact(4)` → ... → `fact(1)`，栈逐层向下增长 48 字节。基线条件（`n <= 1` 返回 1）保证递归收敛，否则栈溢出。

### 2.6 为什么入口直接 `ret` 不靠谱

入口栈顶的返回地址属于 `KERNEL32!BaseThreadInitThunk` 的内部流程。`ret` 之后继续执行依赖启动代码自己的栈状态——这不是给用户程序准备的退出路径，退出码也无法控制。实测入口直接 `ret` 会导致进程挂起。

**结论：正式程序一律调用 `ExitProcess`（或 `ExitThread`），不要靠入口 `ret` 退进程。**

### 2.7 用具体地址走完一次调用

数字比单看箭头更容易验证。假设 `_start` 刚进入时 `RSP=0x7008`，满足 `%16==8`：

```text
_start: sub rsp,40
RSP = 0x7008 - 0x28 = 0x6FE0，此时 %16==0

_start: call fact
返回地址压到 [0x6FD8]，RSP=0x6FD8，fact 入口 %16==8

fact: push rbp
旧 RBP 写到 [0x6FD0]，RSP=0x6FD0

fact: mov rbp,rsp
RBP=0x6FD0

fact: sub rsp,32
RSP=0x6FB0，仍然 %16==0
```

第一层 `fact` 的栈帧如下：

```text
高地址
0x6FE0  _start 调用前的 RSP
0x6FD8  返回地址（回到 _start 的 call 下一条）
0x6FD0  保存的旧 RBP，当前 RBP 指向这里
0x6FCF  ┐
 ...    │ fact 当前分配的 32 字节
0x6FB0  ┘ 当前 RSP
低地址
```

第一层保存的 `n=5` 位于 `[RBP-4]=[0x6FCC]`。执行递归 `call fact` 时，返回地址写到 `[0x6FA8]`，第二层入口 RSP 从第一层的 `0x6FD8` 变成 `0x6FA8`：

```text
0x6FD8 - 0x6FA8 = 0x30 = 48 字节
```

这 48 字节正好是：第一层分配的 32 字节 + 第二层返回地址 8 字节 + 第二层保存的旧 RBP 8 字节。注意“每层 48”比较的是**相邻两次函数入口的 RSP**；仅看 `call` 的一瞬间只压入 8 字节。

返回时顺序完全相反：

```text
leave 的 mov rsp,rbp：RSP 0x6FB0 → 0x6FD0，局部空间不再有效
leave 的 pop rbp：   恢复旧 RBP，RSP 0x6FD0 → 0x6FD8
ret：                弹出返回地址，RSP 0x6FD8 → 0x6FE0
```

恢复后的 RSP 与调用前完全一致，这就是“栈平衡”。

### 2.8 递归返回值如何逐层变成 120

递归不是五份代码同时运行，而是同一个函数标签拥有五个不同栈帧。每一帧保存自己的 `n`：

| 当前帧 | 调用前保存的 n | 等下一层返回后计算 | 本层 EAX 返回值 |
|---|---:|---|---:|
| fact(1) | 1 | 基线直接返回 1 | 1 |
| fact(2) | 2 | `1×2` | 2 |
| fact(3) | 3 | `2×3` | 6 |
| fact(4) | 4 | `6×4` | 24 |
| fact(5) | 5 | `24×5` | 120 |

调用链向下时 ECX 依次变为 5、4、3、2、1；返回链向上时 EAX 依次变为 1、2、6、24、120。每一层从自己的 `[RBP-4]` 恢复 `n`，所以不会误用其他层的值。

递归至少需要：

1. 能结束的基线条件，这里是 `n<=1`；
2. 每次调用让问题更接近基线，这里是 `n-1`；
3. 在有限栈空间内完成，层数过深会栈溢出。

### 2.9 通用栈帧大小怎样算，而不是背 32 或 48

对使用 `push rbp; mov rbp,rsp` 且还会调用其他函数的函数，可以先按下面估算：

```text
需要的栈分配量 = 局部变量 + 额外保存区 + 至少 32 字节 outgoing 影子空间
再向上取整到 16 的倍数，保证 call 前 RSP%16==0
```

例如局部变量 4 字节、没有额外保存区、还会调用其他 ABI 函数：

```text
4 + 32 = 36 → 向上取整到 48
```

因此通用写法是 `sub rsp,48`，不是 `sub rsp,36`，因为 36 会破坏 16 字节对齐。若还有 `push rbx/push r15` 等保存非易失寄存器的操作，每push一次 RSP 又减 8，必须重新计算；不能只在函数末尾机械补一个 `sub rsp,40`。

安排布局时，让局部变量与 `[rsp]`～`[rsp+31]` 的 outgoing 影子空间分开。调用返回后，局部变量应仍在；影子空间内容则允许已被被调者改写。

### 3.2 `.lst` 摘录

```text

    27 00000004 B905000000                  mov ecx, 5
    28 00000009 E807000000                  call fact
    31 0000000E 89C1                        mov ecx, eax
    32 00000010 E8(00000000)                call ExitProcess

    45 00000016 4889E5                      mov rbp, rsp

```

- `E807000000`：`call fact` 相对位移 +7。

- `C9` / `C3`：`leave` / `ret`。

### 3.3 GDB 观察栈帧

```text
fact(5) 入口    rsp = 0x...f8   (%16 == 8)
序言后          rsp = 0x...d0   rbp = 0x...f0
fact(4) 入口    rsp = 0x...c8   (比上一次入口低 0x30 = 48 字节)
```

每次递归固定下降 48 字节，与知识点 2.5 的推导一致。

## 4. 代码重点讲解

1. **入口 `sub rsp, 40`（知识点 2.3）**：入口 `RSP%16==8`，减 40 后 `%16==0`，所以 `call fact` 合法。`fact` 的返回值在 `EAX`，直接作为退出码。
2. **标准栈帧（知识点 2.4）**：`push rbp` → `%16==0`，`mov rbp, rsp` 建立帧指针，`sub rsp, 32` 留影子空间。此后函数体内再 `call fact` 仍然对齐。
3. **把 `n` 存到 `[rbp-4]`**：递归调用 `fact(n-1)` 会覆盖 `ECX`，所以调用前把 `n` 保存到当前私有栈帧。`[rbp-4]` 位于已分配区域内，并且当前 `fact` 实现不写调用者影子空间，所以本例可正确运行；若改调任意 ABI 函数，应按知识点 2.4/2.9 增加独立的局部变量区，不能假设影子空间会保值。
4. **`lea ecx, [rcx - 1]`**：用 `lea` 做减法（`rcx-1`），不影响标志位，比 `dec` + 处理副作用更干净。
5. **`imul eax, ecx`**：把 `(n-1)!`（在 `EAX`）乘上 `n`（从 `[rbp-4]` 恢复到 `ECX`）。
6. **`leave; ret`**：`leave` 恢复 `RSP` 和 `RBP`，`ret` 弹出返回地址。

## 5. 常见坑

1. **`call` 前忘记对齐**：不 `sub rsp, 40` 直接 `call`，被调方入口 `%16==0`，违反 ABI。简单函数可能侥幸能跑，调用 SSE 或系统 API 时容易崩。
2. **序言只 `sub rsp, 24`**：`8+24=32`，`RSP%16` 仍是 8，`call` 依然错位。要凑到 16 的倍数。
3. **以为 Windows 有红区**：没有。`[rsp-8]` 是未分配区域，`call` 会覆盖。
4. **影子空间只留 8 字节**：Windows x64 要求 32 字节。
5. **本地槽超出分配范围**：`sub rsp, 32` 后只有 `[rbp-32]` 到 `[rbp-1]` 已分配；越界访问无效。并且通用 ABI 函数不能把其中与 outgoing 影子空间重叠的区域当作调用后仍保值的局部变量，必要时应改为 `sub rsp,48` 等布局。
6. **递归不收敛**：缺基线条件会栈溢出。
7. **`leave` 后再访问本地变量**：`leave` 已把 `RSP` 抬回 `RBP`，本地槽全部失效。
8. **靠入口 `ret` 退出**：退出码不可控，实测挂起；用 `ExitProcess`。
