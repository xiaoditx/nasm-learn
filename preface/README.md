# 前言：汇编学习路线与术语参考

这份前言默认你理解变量、函数、条件、循环和源码编译等高级语言常识，但不预设寄存器、机器码、计算机组成或 Windows 内部原理。它同时是**最小入门说明**和**术语参考页**，不需要从第一页一路背到最后一页才开始编程。

本教程讲的是 **Windows 10/11 上的 64 位 x86 汇编，语法使用 NASM**。它不适用于 16 位 DOS、32 位 x86、ARM，也不使用 MASM 语法。

## 1. 汇编语言到底是什么

CPU 只执行机器码，也就是一串字节。例如：

```text
机器码（十六进制）：B9 2A 00 00 00
汇编写法：          mov ecx, 42
含义：              把整数 42 放进 ECX 寄存器
```

汇编语言是机器码的**可读文本形式**。它不是 Windows 脚本，也不是高级语言的替代品：

- 一条汇编指令通常只完成一个很小的动作；
- 没有自动变量类型、自动内存管理和自动错误检查；
- 寄存器、栈、参数传递和对象生命周期都要由程序员明确安排；
- 汇编器会做语法检查和指令编码，但不会替你保证程序逻辑正确。

本教程中的程序仍然运行在 Windows 的保护模式下。窗口、文件、控制台、Direct2D 等功能最终都要通过操作系统或系统库完成，并不是“写了汇编就能绕过系统”。

### 1.1 从文本到运行的完整过程

```text
hello.asm                 人写的 NASM 源文件
    │  nasm（汇编器）
    ▼
hello.obj                 目标文件：机器码 + 符号 + 待修正位置
    │  ld（链接器）+ kernel32 导入库
    ▼
hello.exe                 PE（Windows 可执行文件）：代码、数据与入口、依赖信息
    │  双击或在终端运行，Windows 加载器
    ▼
进程中的地址空间          加载程序和动态链接库（DLL），准备外部函数地址
    │  跳到入口 _start
    ▼
CPU 逐条执行指令           需要系统服务时调用 Windows 应用程序接口（API）
```

这里最容易混淆的是：

- **汇编**：把指令文本翻译成机器码，生成 `.obj`，还不是完整程序；
- **链接**：组合目标文件和库，解析 `ExitProcess` 等外部符号，生成 `.exe`；
- **加载**：运行 `.exe` 时，Windows 把它映射到进程虚拟内存并准备依赖；
- **执行**：CPU 从入口开始取指令、解码、执行。

### 1.2 指令和数据都是字节

代码段里的 `B9 2A 00 00 00` 会被 CPU 当指令执行；数据段里的相似字节可能只是文本或整数。区别在于**CPU 是否把它当指令地址执行**，不在于字节外观。

因此：

- 不要跳转到数据区执行；
- 不要把代码地址当成字符串；
- 调试器既能用 `x/i` 把字节反汇编成指令，也能用 `x/b` 把它们显示成普通数据。

## 2. 位、字节、进制与有符号数

### 2.1 位和字节

**位（bit）**只能表示 0 或 1，**字节（byte）**固定为 8 位。x64 文档里还常见这些名字：

| 名称 | 位数 | 字节数 | 可表示的无符号范围 |
|---|---:|---:|---|
| byte | 8 | 1 | 0～255 |
| word | 16 | 2 | 0～65,535 |
| dword | 32 | 4 | 0～4,294,967,295 |
| qword | 64 | 8 | 0～2⁶⁴−1 |

“64 位程序”主要指通用寄存器和地址通常为 64 位，**不代表每条指令都是 64 位，也不代表每个整数都必须占 8 字节**。

### 2.2 为什么汇编里到处都是十六进制

十进制适合日常计数；二进制直接对应位；十六进制用 `0～9、A～F` 表示 0～15，恰好对应 4 个二进制位，所以特别适合看机器码、掩码和地址。

| 十进制 | 二进制 | 十六进制 |
|---:|---:|---:|
| 0 | 0000 | 0x0 |
| 1 | 0001 | 0x1 |
| 2 | 0010 | 0x2 |
| 8 | 1000 | 0x8 |
| 9 | 1001 | 0x9 |
| 10 | 1010 | 0xA |
| 15 | 1111 | 0xF |
| 16 | 0001 0000 | 0x10 |
| 42 | 0010 1010 | 0x2A |
| 255 | 1111 1111 | 0xFF |

NASM 中写 `0x2A`、`0b101010`；调试器通常也显示 `0x...`。`2A` 与 `0x2A` 是同一个数，不是字符串。

### 2.3 手工换算：不依赖计算器

**十六进制转二进制**：每个十六进制数字独立展开成 4 位。

```text
0x2A = 0010 1010
       2    A

0xB8000 = 1011 1000 0000 0000 0000
          B    8    0    0    0
```

**二进制转十六进制**：从右往左每 4 位一组，不足在左侧补 0。

```text
10 1010 → 0010 1010 → 0x2A
```

**十六进制转十进制**：按 16 的幂展开。

```text
0x2A  = 2×16 + 10 = 42
0x100 = 1×16² = 256
0x1234 = 1×16³ + 2×16² + 3×16 + 4 = 4660
```

**十进制转十六进制**：反复除以 16，余数从下往上读。

```text
234 ÷ 16 = 14 余 10（A）
 14 ÷ 16 =  0 余 14（E）
所以 234 = 0xEA
```

常用换算值得熟记：`0x10=16`、`0x20=32`、`0x28=40`、`0x30=48`、`0x100=256`、`0x400=1024`。教程中的栈大小 `40` 是十进制，写成十六进制就是 `0x28`，机器码里会看到 `28`。

### 2.4 按位运算不是算术运算

把两个整数逐位对齐后运算：

```text
  0010 1010   (0x2A)
& 0000 1111   (0x0F)
= 0000 1010   (0x0A)    and：两位都为 1 才是 1

  0010 1010
| 0000 1111
= 0010 1111   (0x2F)    or：任一位为 1 就是 1

  0010 1010
^ 0000 1111
= 0010 0101   (0x25)    xor：两位不同才是 1
```

常见用途：

- `and eax, 0xFF`：只保留低 8 位，其余清零；
- `or flags, 4`：把 bit 2 置为 1，不动其他位；
- `xor eax, eax`：把 EAX 清零；
- `test eax, 1`：用 AND 的结果设置标志位，但不保存结果，从而判断最低位。

### 2.5 负数如何存：补码

固定位宽下，有符号数使用二进制补码。以 8 位为例：

```text
 1 = 0000 0001
-1 = 1111 1111 = 0xFF
 0 = 0000 0000
```

手工求 `-1`：先把 `1` 按位取反得到 `1111 1110`，再加 1 得到 `1111 1111`。

同一串字节的含义取决于解释方式：

| 位模式 | 当作无符号 8 位数 | 当作有符号 8 位数 |
|---|---:|---:|
| `0x7F` | 127 | 127 |
| `0x80` | 128 | -128 |
| `0xFF` | 255 | -1 |

CPU 的 `add/sub` 电路对两种解释通常相同，但**比较、除法和扩展必须区分**：

- 无符号：`jb/ja`、`div`、`movzx`；
- 有符号：`jl/jg`、`idiv`、`movsx`。

### 2.6 位宽、截断与溢出

N 位寄存器只能保存 N 个位。例如 8 位无符号数 `255 + 1` 的数学结果是 256，但 AL 只能留下低 8 位：

```text
1111 1111 + 1 = 1 0000 0000
AL 中保存       =   0000 0000 = 0
多出的第 9 位由 CF 记录
```

这不是“数字消失”，而是固定位宽运算的回绕。读取标志位、选择足够宽的寄存器、在窄数据与宽数据之间正确扩展，都是汇编程序员的工作。

## 3. CPU、寄存器与指令执行模型

### 3.1 CPU 在哪里保存正在计算的值

可以把存储粗略分成：

| 位置 | 速度/容量特征 | 本教程中的例子 |
|---|---|---|
| 寄存器 | CPU 内部，最快、数量少 | `RAX`、`RCX`、`RSP` |
| 内存 | 进程运行时的工作区，容量大 | 全局变量、栈、堆、窗口结构体 |
| 磁盘文件 | 持久保存，程序不直接当寄存器用 | `.asm`、`.exe`、数据文件 |

`mov eax, 1` 只改寄存器；`mov [rel value], eax` 才把值写入内存。程序退出后，寄存器和普通内存中的值都不会自动保存到文件。

### 3.2 CPU 如何执行程序

简化地说，CPU 反复做三件事：

```text
取指：从 RIP 指向的地址读取指令字节
解码：判断这是什么指令、操作数在哪里、占多少字节
执行：改寄存器/内存/标志位，并确定下一条 RIP
```

`RIP` 是当前指令指针。普通指令执行后通常前进到下一字节位置；`jmp`、条件跳转、`call`、`ret` 会改变正常顺序。

汇编源码中的一行不一定只占一个字节。例如：

```asm
mov ecx, 42       ; 5 字节
sub rsp, 40       ; 4 字节
ret               ; 1 字节
```

所以不能用“源码行号 × 指令长度”猜地址，应查看 `.lst` 或反汇编。

### 3.3 通用寄存器与专用角色

x64 有 16 个通用寄存器：`RAX/RBX/RCX/RDX/RSI/RDI/RBP/RSP/R8～R15`。“通用”不表示完全随意：

- `RSP` 必须始终作为栈指针谨慎维护；
- `RBP` 常用作栈帧基准；
- Windows 调用约定规定 `RCX/RDX/R8/R9` 传前四个整数参数；
- 返回值通常放 `RAX`；
- `div` 等指令还会隐式使用特定寄存器。

第 01 章会完整介绍寄存器；当前只需理解“寄存器是有名字、有固定位宽的临时存储格”。

### 3.4 一条指令的操作数

```asm
mov ecx, 42
```

- `mov` 是助记符，表示做什么；
- `ecx` 是目的操作数；
- `42` 是源操作数，这里是立即数；
- NASM 的顺序是 `指令 目的, 源`。

常见操作数形式：

```asm
mov eax, 1                 ; 立即数 → 寄存器
mov eax, ebx               ; 寄存器 → 寄存器
mov eax, [rel value]       ; 内存 → 寄存器
mov [rel value], eax       ; 寄存器 → 内存
lea rax, [rel value]       ; 计算 value 的地址 → RAX，不读取该地址内容
```

方括号表示地址表达式。最直观的理解：

```text
value       在 NASM 表达式里可表示与标签有关的数值
[value]     访问这个地址中的内容
lea ...     只计算地址，不访问内容
```

本教程访问全局数据统一写 `[rel 名称]`，明确使用 RIP 相对寻址，后续章节会解释原因。

### 3.5 RFLAGS：条件跳转的依据

算术和逻辑指令通常会更新标志位：

| 标志 | 名字 | 简化含义 |
|---|---|---|
| ZF | Zero Flag | 结果是否为 0 |
| CF | Carry Flag | 无符号加法进位/减法借位等 |
| SF | Sign Flag | 结果最高位是否为 1 |
| OF | Overflow Flag | 有符号运算是否溢出 |

`cmp a, b` 内部做 `a-b`，但不保存差，只保留标志。随后 `je/jne/jb/jl` 等读取标志决定是否跳转。

注意两条指令之间的距离：如果在 `cmp` 和条件跳转之间插入会改标志的指令，判断依据就可能被覆盖。

## 4. 内存、地址、指针与小端

### 4.1 内存是一排带地址的字节

在教程使用的扁平虚拟内存模型里，可以把进程内存想成：

```text
地址       内容
0x1000     0x56
0x1001     0x34
0x1002     0x12
0x1003     ...
```

地址每增加 1，就走到下一个字节。一个 64 位地址本身占 8 字节，但它指向的数据可以是 1、2、4、8 字节或更长。

现代 Windows 程序看到的是**虚拟地址**，不是物理内存条上的固定位置。不同进程可以有相同数值的虚拟地址，但映射到不同物理内存；不能凭一个地址访问别的进程，也不能直接访问 DOS 时代的物理显存。

### 4.2 指针就是“保存地址的值”

如果 `p` 中保存了变量 `value` 的地址，那么 `p` 就是指针：

```asm
lea rax, [rel value]   ; RAX = value 的地址
mov ecx, [rax]         ; 从这个地址读 4 字节到 ECX
```

这里读取宽度由 `ECX` 决定，所以是 4 字节。指针没有自动携带“指向几个字节”的信息，宽度必须由指令和类型约定明确。

二级指针也只是多一层：

```text
pp → p → value
```

每用一次方括号，通常就是按当前地址取一次内容；具体宽度仍要看指令。

### 4.3 小端字节序

x86/x64 使用小端：多字节整数的**最低有效字节存在最低地址**。

```asm
value dd 0x12345678
```

内存布局为：

```text
低地址                                                   高地址
  │+0         │+1         │+2         │+3
  0x78        0x56        0x34        0x12
```

因此：

```asm
mov eax, [rel value]        ; EAX = 0x12345678，CPU 按小端重组
movzx eax, byte [rel value] ; EAX = 0x78，只读最低地址的 1 字节
```

调试器按字节查看内存时会看到“倒过来”的数字，这不是存错了。

### 4.4 对齐

“地址按 N 对齐”就是地址能被 N 整除。例如 8 字节对齐地址的十六进制末位只能是 `0` 或 `8`。

对齐主要为了：

- 满足 ABI 和某些指令的硬性要求；
- 让结构体字段位于 CPU/编译器预期的位置；
- 避免额外访存代价。

`align 8` 会让当前输出位置前进到下一个 8 的倍数，中间可能插入填充字节。对齐不是给变量值补零，而是调整**地址**。

### 4.5 数组与寻址公式

若数组每个元素占 S 字节，第 i 个元素（从 0 开始）的地址为：

```text
元素地址 = 数组首地址 + i × S
```

例如 qword 数组：

```asm
mov rax, [rsi + rdx*8]   ; RSI=首地址，RDX=i，每元素 8 字节
```

x64 寻址中的比例因子只能是 1、2、4、8。其他元素大小要用 `imul/shl` 等先计算偏移。

## 5. 栈、函数调用与 Windows x64 ABI

### 5.1 栈是什么

栈是一块按“后进先出”使用的内存，`RSP` 指向当前栈顶。x64 栈向低地址增长：

```asm
push rax    ; RSP = RSP - 8，再把 RAX 写到新栈顶
pop  rbx    ; 从栈顶读 8 字节到 RBX，再 RSP = RSP + 8
```

“向下增长”只表示地址变小，不表示数据上下颠倒。

`call func` 会把下一条指令地址压栈再跳转；`ret` 弹出这个地址并返回。二者必须配对，栈顶如果被覆盖，`ret` 就会跳到错误地址。

### 5.2 ABI 为什么必须存在

两个函数可能由不同人、不同编译器生成。要让它们互相调用，必须事先约定：

- 参数放哪里；
- 返回值放哪里；
- 哪些寄存器调用后仍保持原值；
- 栈如何对齐、由谁恢复；
- 栈上哪些区域双方都能使用。

这套约定叫 **ABI（应用程序二进制接口）**。本教程使用 Microsoft Windows x64 ABI，不要直接套用 Linux 的 System V ABI。

### 5.3 四个参数寄存器与返回值

整数或指针参数依次放：

```text
第 1 个：RCX     第 2 个：RDX     第 3 个：R8     第 4 个：R9
```

第 5 个及以后放栈上。整数返回值通常在 `RAX`，32 位返回值通常写 `EAX`。

例如：

```c
ExitProcess(42);
```

对应核心汇编：

```asm
mov ecx, 42
call ExitProcess
```

浮点参数使用 XMM 寄存器，对应规则会在 Direct2D 章节用到时再展开。

### 5.4 影子空间不是“可选优化”

每次 `call` 前，调用者必须在自己的栈帧中预留 32 字节，给被调函数临时保存前四个参数寄存器使用。这叫影子空间（shadow space / home space）。

它不等于：

- 被调函数的局部变量总大小；
- 只给四个参数各复制一次的强制要求；
- 可以放返回后仍需长期保存的数据区域。

被调函数返回后，调用者可以继续使用自己栈帧中的该区域，但其中原有内容应视为可能已被覆盖。

### 5.5 16 字节对齐与 `sub rsp, 40` 的推导

本教程约定：**执行 `call` 之前，RSP 必须 16 字节对齐**。`call` 自身再压入 8 字节返回地址，所以普通被调函数入口看到 `RSP % 16 == 8`。

对教程的 `_start` 入口也按这一状态处理：

```text
入口 RSP % 16 = 8
需要减 8，才能让 RSP % 16 变成 0
还要至少预留 32 字节影子空间
所以共减 8 + 32 = 40 字节
40 % 16 = 8，因此减 40 后恰好对齐
```

```asm
sub rsp, 40       ; 十进制 40 = 十六进制 0x28
```

不能机械地把所有函数都写成 `sub rsp, 40`：如果已经 `push rbp`，栈又改变了 8 字节，常用组合就变成 `push rbp; mov rbp,rsp; sub rsp,32`。第 05 章会用地址图完整推导。

### 5.6 易失与非易失寄存器

| 分类 | 寄存器 | 调用后的预期 |
|---|---|---|
| 易失 | `RAX/RCX/RDX/R8～R11` | 被调函数可以覆盖，调用者不能假设原值还在 |
| 非易失 | `RBX/RBP/RSI/RDI/RSP/R12～R15` | 被调函数若使用，必须保存并恢复 |

“非易失”不是寄存器自动保存，而是**被调者负责**恢复。写函数时若使用 RBX，却不保存恢复，就破坏了调用者；调用函数时若把重要值只放 RCX，又不保存，就可能被 API 覆盖。

### 5.7 栈帧与局部变量

典型栈帧：

```text
高地址
[RBP+8]   返回地址
[RBP]     调用者旧 RBP
[RBP-4]   局部变量 n
...       本函数分配的栈空间
[RSP]     当前栈顶
低地址
```

`RBP` 在函数期间保持稳定，便于用固定偏移访问局部变量。`leave` 恢复 `RSP/RBP`，随后 `ret` 返回。

局部变量区要和**下一次调用的 outgoing 影子空间**分开。被调函数允许写 `[RSP]`～`[RSP+31]`，所以这里不能同时存放调用返回后仍要使用的局部变量。使用 `push rbp; mov rbp,rsp` 后，若需要 4 字节局部变量并调用其他 ABI 函数，常见分配量是 `4+32=36` 向上对齐到 `48`，而不是让二者重叠。

栈上的局部变量只在本函数活动期间有效。函数返回后继续保存并访问该地址，属于悬空指针。

## 6. 目标文件、PE、DLL 与导入表

### 6.1 `.obj` 为什么不能直接运行

目标文件里可能只有机器码片段和符号信息。例如源码调用 `ExitProcess`：

- NASM 知道这个函数在外部，但不知道最终地址；
- 它留下一个待链接器修正的位置；
- `global _start` 告诉链接器哪个符号可以对外可见；
- `extern ExitProcess` 告诉汇编器不要在本文件寻找其定义。

链接器把各段布置好、解析符号、补上能确定的地址，才生成完整 PE。

### 6.2 符号、重定位与节区

| 名词 | 含义 |
|---|---|
| 符号 | 给标签、函数、变量起的可链接名字，如 `_start` |
| 重定位 | 最终布局确定后，修正指令中的地址或位移 |
| 节区/段 | 按用途组织内容，如 `.text`、`.data`、`.bss` |

`.lst` 中括号包起来的地址或 `?` 往往表示“当前还无法确定/不占文件字节”，不一定是错误。

### 6.3 PE 文件不是纯粹的一串机器码

PE（Portable Executable）包含：

- PE/DOS 头：向 Windows 描述文件；
- 节表：说明代码和数据放在哪里、有多大、权限如何；
- `.text` 等实际节内容；
- 导入表：列出需要哪些 DLL、哪些函数；
- 可选的导出表、资源、重定位信息等。

常见地址术语：

- **文件偏移**：字节在 `.exe` 文件中的位置；
- **RVA**：相对于模块装载基址的偏移；
- **VA**：运行时的虚拟地址；
- **ImageBase**：PE 头记录的首选装载基址；
- **ASLR**：系统可能把模块装到不同基址，因此运行时 VA 可与静态分析显示值不同。

```text
未启用/不考虑 ASLR 时：VA = ImageBase + RVA
启用 ASLR 时：运行时 VA = 实际装载基址 + RVA
```

### 6.4 DLL、导入库与 API 调用

`kernel32.dll` 是运行时提供系统函数的动态库；`-lkernel32` 找到的 `libkernel32.a` 是链接时使用的**导入库**，不是把 kernel32 全部代码复制进你的 EXE。

简化流程：

```text
你的 call ExitProcess
    → 链接器生成/选择的导入跳板
    → PE 导入地址表中的函数指针
    → Windows 加载器在启动时填入 kernel32!ExitProcess 的实际地址
```

`objdump -p hello.exe` 能看到 `DLL Name: KERNEL32.dll` 和导入函数名。本教程说的“无 CRT”是**不依赖 C 运行时库**，不等于“不调用任何 DLL”；程序仍可以调用 kernel32/user32/d2d1 等系统 DLL。

### 6.5 CRT 是什么

CRT（C Runtime）提供 C 程序常用启动代码与库函数，例如 `printf`、`malloc`、字符串处理等。使用 CRT 时，程序入口通常先进入运行库初始化，再转到 `main`。

本教程：

- 第 00～05 章直接从 `_start` 开始，只调系统 API；
- 第 06～19 章按各章设置使用 UCRT/MinGW 工具链与库；
- 第 20 章以后系统分析并实践不依赖 CRT 的入口和程序。

“汇编程序”并不自动等于“无 CRT”，是否依赖要看链接方式和导入表。

## 7. 工具准备与第一次验证

### 7.1 需要的工具

| 工具 | 作用 | 验证命令 |
|---|---|---|
| NASM | 汇编 `.asm` | `nasm --version` |
| MinGW-w64 UCRT64 的 `ld` | 链接 PE | `ld --version` |
| `objdump` | 查看 PE、反汇编 | `objdump --version` |
| GDB | 指令级调试 | `gdb --version` |
| Make（第 06 章起） | 自动执行构建规则 | `make --version` |

推荐从 MSYS2 的 **UCRT64** 环境取得一致的一套 MinGW 工具。教程示例库目录为 `C:/msys64/ucrt64/lib`；如果你的 MSYS2 安装在其他位置，要同步修改 `-L` 路径和 Makefile 配置。

NASM 与 MinGW 是不同工具：NASM 负责汇编，`ld/objdump/gdb` 通常来自 MinGW 工具链。

### 7.2 在 PowerShell 中检查

```powershell
nasm --version
ld --version
objdump --version
gdb --version
make --version
Test-Path "C:\msys64\ucrt64\lib\libkernel32.a"
```

最后一项应输出 `True`。如果命令提示“无法识别”，通常是未安装或 PATH 未配置，不是汇编源码错误。

### 7.3 目录与命令执行规则

每条命令都要在对应章节目录执行。例如：

```powershell
Set-Location "C:\Users\Administrator\Documents\nasm-learn\00-toolchain"
nasm -f win64 -l hello.lst -o hello.obj hello.asm
```

之后学习其他章节时，把路径末尾换成对应目录。README 的 `nasm ... hello.asm` 依赖当前目录，不能在任意目录原样执行。

PowerShell 运行当前目录程序要写：

```powershell
.\hello.exe
$LASTEXITCODE
```

`$LASTEXITCODE` 是上一个原生进程返回的退出码。很多早期章节**故意不打印文字**，结果只通过退出码表达；不显示窗口或文字不代表没运行。

如果 PowerShell 的当前位置不是你的实际教程路径，请以实际路径为准，不必照抄用户名。

### 7.4 构建产物分别是什么

| 文件 | 是否源码 | 用途 |
|---|---|---|
| `.asm` | 是 | 人工编辑的汇编源码 |
| `.obj` | 否 | NASM 生成的目标文件 |
| `.exe` | 否 | 链接后可直接运行的 PE |
| `.lst` | 否 | 源码、偏移和机器码对照清单 |

修改 `.asm` 后必须重新执行汇编和链接；只改 `.lst` 不会改变程序。

### 7.5 先分清错误发生在哪一步

```text
nasm 报错       → 源码语法、操作数宽度、符号拼写等
ld 报错         → 缺目标文件、入口/外部符号、库路径等
运行时报错/崩溃  → 地址、栈、参数、生命周期等运行时问题
结果不符        → 用退出码、GDB、反汇编逐步核对
```

不要一看到错误就反复运行同一条完整命令。先读第一条错误信息，确认阶段和行号。

## 8. 清单、反汇编与 GDB 的最小用法

### 8.1 `.lst` 与 `objdump` 分工

`.lst` 由 NASM 生成，适合回答：

- 这条源码编码成哪些字节？
- 数据在段内的偏移是多少？
- 哪些地址尚待链接器修正？

`objdump` 读取链接后的文件，适合回答：

```powershell
objdump -d hello.exe     # 反汇编代码
objdump -h hello.exe     # 查看节区
objdump -p hello.exe     # 查看 PE 头、导入表等
objdump -s -j .data hello.exe  # 按字节显示 .data
```

反汇编地址是链接/加载布局中的地址；`.lst` 的偏移通常是段内偏移，两者不能不加区分地比较。

### 8.2 GDB 最小命令表

```text
gdb .\hello.exe
(gdb) break _start       在入口设断点
(gdb) run                运行到断点
(gdb) disassemble        反汇编当前函数/位置
(gdb) stepi              执行一条机器指令，可缩写 si
(gdb) info registers     查看寄存器
(gdb) info registers rax rsp rip
(gdb) x/8bx $rsp         从 RSP 开始显示 8 个字节，十六进制
(gdb) x/4gx $rsp         显示 4 个 8 字节单位
(gdb) x/i $rip           显示 RIP 处的一条指令
(gdb) continue           继续运行，可缩写 c
(gdb) quit               退出
```

`x` 命令的格式可拆成“数量 + 单位 + 显示方式”：

- `b/h/w/g`：1/2/4/8 字节单位；
- `x/d/u`：十六进制/有符号十进制/无符号十进制；
- `i`：解释为指令。

例如 `x/16bx &msg` 是“从 msg 地址显示 16 个字节”。

### 8.3 推荐的排查顺序

1. 先根据公式或文档写出**预期结果**；
2. 在关键指令前设断点；
3. 执行前记录参数寄存器、RSP 和相关内存；
4. `stepi` 执行一条；
5. 对比实际结果与预期；
6. 如果不符，只改一个变量重新验证。

这比一次性观察整个程序更容易定位问题。

## 9. 本教程的记号、阅读方法与准备清单

### 9.1 记号约定

- `RAX/EAX/AX/AL` 都表示同一寄存器的不同宽度，不是四个独立变量；
- 十进制默认直接写，如 `40`；十六进制写 `0x28`；
- `[地址]` 表示按该地址访问内存；
- `%include`、`%define` 是 NASM 预处理指令，不是 CPU 指令；
- `API` 是系统或库提供的函数接口；调用 API 仍须遵守 ABI；
- README 中的 `←` 后内容是解释，不是要输入的命令；
- 示例输出中的地址可能因 ASLR、工具版本而不同，重点看结构和低 4 位对齐关系。

### 9.2 每章建议这样学

1. 先读“本章目标”，确认要解决的问题；
2. 读完知识点再打开完整源码，不要先背代码；
3. 自己执行构建命令，核对真实输出；
4. 对照 `.lst` 找到至少一条关键指令；
5. 用 GDB 验证至少一个寄存器或内存结论；
6. 做练习时一次只改一处，并预测结果再运行；
7. 出问题时先读“常见坑”，再按错误阶段排查。

不需要一次记住所有指令。应优先掌握：**数据在哪里、多宽、谁拥有它、调用前后什么会变化**。

### 9.3 进入第 00 章前的最小检查

- [ ] 能说出汇编、链接、加载、执行的区别；
- [ ] 能把 `0x2A` 换算成 42，知道一个字节有 8 位；
- [ ] 知道寄存器是 CPU 内部的小块存储，指令会改变寄存器或内存；
- [ ] `nasm/ld/objdump/gdb` 都能执行（GDB 可以等到首次调试练习再熟悉）；
- [ ] 会在 PowerShell 中进入章节目录并读取 `$LASTEXITCODE`。

小端、`call/ret`、参数寄存器和影子空间**不是进入第 00 章前的验收项**，它们分别属于后续学习节点。准备好后进入 [第 00 章：NASM 源码骨架与第一个 Windows 程序](../00-toolchain/README.md)。
